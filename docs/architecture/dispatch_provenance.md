# Dispatch provenance: recording where a workspace's text came from

**Source:** `alan/dispatch_provenance.py`, `alan/workspace.py`, `alan/prep_chat.py`, `alan/routes/workspaces.py`, `alan/reconciler.py`, `alan/teams/dependency_sweep.py`, `alan/project_auto_continue.py`, `tests/dispatch_provenance_gate.py`.

Every workspace's dispatched `title`/`description` is already durable — `Meta.description` is written once at `create()` and never touched by any update site. Nothing, however, recorded *which creation path* produced that text, so a labelled corpus of brief-to-outcome pairs could not be assembled after the fact: a measurement of the existing fleet could not tell which workspaces came from a human typing into build-chat versus an automated driver versus the recurring dependency sweep. `alan.dispatch_provenance` records that provenance prospectively, at creation, on every one of the five creation paths that call `alan.workspace.create` — the public API route plus four internal callers that bypass it entirely.

## Two independent parts

`DispatchProvenance` (`alan/dispatch_provenance.py`, `frozen=True`) has three fields:

- **`surface: DispatchSurface`** — a closed, server-derived enum naming which creation path ran. Never spoofable: no request field ever sets it directly. The public API route derives it from `prep_chat.dispatch_surface(body.prep_chat_kind)`, and each internal caller passes its own literal member.
- **`actor: str | None`** — an optional, caller-declared label naming the automation that drove the dispatch, absent by default. Validated for **shape**, not membership (`Field(min_length=1, max_length=64, pattern=r"^[a-z0-9][a-z0-9_-]*$")`), so a driver skill nobody has enumerated today can start supplying an actor label later without any schema change — a one-line edit to that skill's dispatch payload, not a PR against this module.
- **`prep_chat_session_id: str | None`** — the identifier of the build/explore chat conversation that produced this text, taken directly from the create request (`body.prep_chat_session_id`), never from `prep_chat.load_ref(ws.path)` or any check for whether an archive directory exists. This is deliberate: **the field means "the conversation that produced this text," never "this workspace has an archived prep-chat directory."** A workspace created from a conversation that is never archived (because `team` was omitted on the create call — see `prep_chat.md`) still carries this link. No consumer of this field may read the stronger, archive-presence meaning into it.

`DispatchSurface` has exactly ten members: `UNRECORDED` (the default — see below), `API_DIRECT` (a direct API call carrying no deliberation artifact), `BUILD_CHAT`, `EXPLORE_CHAT`, `TRIAGE_SWEEP`, `DEP_SWEEP_PARENT` (the recurring per-repo "Dependency Sweep" parent workspace), `DEP_SWEEP_PR` (the per-PR workspace `_ensure_pr_workspace` creates or reuses), `DEP_ADVISORY_CHECK` (the hidden per-engine "Dependency Advisory Check" workspace the triage hook seeds), `DEP_ADVISORY_FIX` (the visible `sec/<package>: <advisory>` fix, no-fix and posture workspaces the advisory check opens), and `PROJECT_AUTO_CONTINUE`. `DEP_SWEEP_PARENT` and `DEP_SWEEP_PR` are kept as two distinct members rather than one collapsed `DEP_SWEEP` value, because they are structurally different corpora (one recurring coordinator workspace per repo vs. one workspace per dependency PR) and collapsing them later is trivial while splitting rows already written with one merged value is not.

`UNRECORDED: Final[DispatchProvenance]` is the module's singleton not-recorded value — `DispatchProvenance(surface=DispatchSurface.UNRECORDED)`, `actor=None`, `prep_chat_session_id=None`.

## Storage: a total field with an explicit default

`Meta.dispatch_provenance: provenance_mod.DispatchProvenance = Field(default_factory=lambda: provenance_mod.UNRECORDED)` is **total**, not required. This is the load-bearing choice for backward compatibility: the several hundred `meta.json` records already on disk before this change have no `dispatch_provenance` key at all, and pydantic's default-factory fills it with `UNRECORDED` on every read. `read()` (which raises `WorkspaceError` on a genuinely malformed record) and `list_workspaces()` (which swallows a `WorkspaceError` and silently skips that row) both keep their existing behavior unchanged — a pre-change record validates cleanly through both, and only a record with an actively malformed `dispatch_provenance` value (e.g. an unknown `surface` string) hits the existing raise/skip paths. There is deliberately **no backfill**: the provenance of pre-change workspaces is gone, and `UNRECORDED` is the correct, honest answer for them — not a guess.

`workspace.create` takes a keyword-only `provenance: DispatchProvenance = provenance_mod.UNRECORDED` **with a default**, not a required parameter. A required parameter cannot gate the highest-volume creator anyway: `routes.workspaces.create_workspace` hands `workspace_mod.create` to `run_in_threadpool` **as a value** (`run_in_threadpool(workspace_mod.create, body.title, ..., provenance=...)`), so the keyword is supplied at the `run_in_threadpool` call, not enforced by `create`'s own signature. Supply is enforced structurally instead — see the gate below.

## The creation paths

| path | site | surface |
|---|---|---|
| public API | `alan/routes/workspaces.py` (`create_workspace`) | `prep_chat.dispatch_surface(body.prep_chat_kind)`: `None` → `API_DIRECT`, `PrepChatKind.BUILD` → `BUILD_CHAT`, `PrepChatKind.EXPLORE` → `EXPLORE_CHAT` |
| triage sweep | `alan/reconciler.py` (`_seed_triage_sweep_impl`) | `TRIAGE_SWEEP` |
| dep-sweep parent | `alan/reconciler.py` (`_dep_sweep_workspace_if_idle`) | `DEP_SWEEP_PARENT` |
| dep-sweep per-PR | `alan/teams/dependency_sweep.py` (`_ensure_pr_workspace`) | `DEP_SWEEP_PR` |
| advisory check parent | `alan/dep_advisory_seed.py` (`_advisory_workspace_if_idle`) | `DEP_ADVISORY_CHECK` |
| advisory fix / no-fix / posture | `alan/teams/dep_advisory.py` (`_attempt`) | `DEP_ADVISORY_FIX` |
| project auto-continue | `alan/project_auto_continue.py` (`advance_project`) | `PROJECT_AUTO_CONTINUE` |

The public route additionally accepts an optional `dispatch_actor` field on `CreateWorkspaceBody`, validated with the same shape pattern as `DispatchProvenance.actor`, and threads it straight through. **Driver attribution is deliberately incomplete on delivery**: the automations that drive dispatches today (for example an issue driver or a roadmap driver) are configured outside this repository as Claude Code skills, so nothing in this change can make them declare an actor. Until each skill is hand-edited to pass `dispatch_actor`, its dispatches record truthfully as whichever surface it actually used (typically `API_DIRECT` or `BUILD_CHAT`) with `actor=None`. That is accepted: the information is entirely unrecoverable today regardless, and this change reduces recovering it in the future to a one-line edit to the driver skill rather than leaving it permanently impossible.

## Two structural gates, not convention

Both gates live in `tests/dispatch_provenance_gate.py` (a pure AST-walking checker, not itself a collected test module — following the `tests/reexport_facade.py` / `tests/raw_root_resolution.py` precedent) and are exercised by `tests/test_dispatch_provenance_gate.py`, including two assertions that run the checkers over the real `alan/**/*.py` tree and require zero violations.

**Supply gate** (`find_missing_provenance_supply`): resolves, per file, which local names are bound to the `alan.workspace` module (via `import alan.workspace as X` or `from alan import workspace as X`) or directly to `workspace.create` (via `from alan.workspace import create [as X]`), then walks every AST **load** of a matching `create` reference. For each one, it finds the nearest **enclosing** `ast.Call` — which is the call itself for a direct `workspace_mod.create(...)` invocation, but is the *outer* call for `run_in_threadpool(workspace_mod.create, ...)`, since there the reference is passed as a plain argument rather than being called directly — and requires a `provenance=` keyword on that enclosing call. A reference with no enclosing call at all, or an enclosing call missing the keyword, is a violation. This is what makes the gate catch the public route's `run_in_threadpool`-as-a-value shape, which is the highest-volume creator and the one a naive "does `create`'s signature require it" check cannot see at all.

**Immutability gate** (`find_provenance_mutation_writes`): flags the literal string `"dispatch_provenance"` in any **write** position across `alan/**` — as an `ast.Dict` string key (covers `model_copy(update={"dispatch_provenance": X})`), as a `Subscript` assignment target (covers `update["dispatch_provenance"] = x`, a natural way to build an update dict before `model_copy`), and as an `ast.keyword` argument name on any call. It is **not** limited to literal `model_copy(update={...})` dicts, because an update dict can equally be built by subscript writes rather than a literal — a dict-literal-only gate would be blind to that shape on the exact module it is meant to guard. There is exactly one hardcoded exemption, expressed as a module constant (`MUTATION_EXEMPTIONS`): the `Meta(...)` construction call inside `alan/workspace.py`, which legitimately sets the keyword once, at construction, inside `create()`. Every other write site across `alan/**` is a real mutation and fails the gate — this is how "immutable after creation" is enforced rather than merely emergent (the way `description`'s immutability was, before this change, purely a fact that nothing happened to update it).

## Out of scope

- **No read surface.** No new query API, no UI, no exposure in any existing response payload or listing projection. `WorkspaceDetail`/`WorkspaceSummary` do not carry this field.
- **No change to how briefs are written, summarized, or proposed** — the deliberation flow (`build_chat`, `explore_chat`) is untouched; only the already-computed `prep_chat_session_id` is read at creation time.
- **No change to `_archive_prep_chat_best_effort`** or to the rule that a preparation conversation is only archived when a team is supplied on the same create call — archiving relocates the conversation on disk and is a separate concern from recording where its text came from.
